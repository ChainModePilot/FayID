# Глава 1. Введение

## Что такое FayID

FayID — это **унифицированная идентификационная инфраструктура** экосистемы iFay. Она предоставляет согласованный набор механизмов идентификации, привязки и обмена аутентификации для каждого участника экосистемы — реальных физических лиц, создаваемых ими цифровых персон, публичных совместно используемых ролей и организационных сущностей.

> Одной строкой: FayID даёт каждому участнику экосистемы iFay идентичность, которая является проверяемой, отслеживаемой и сохраняющей конфиденциальность.

## Четыре вида субъектов

Система FayID организована вокруг четырёх видов основных субъектов:

| Субъект | Описание |
| --- | --- |
| **Human Prototype** | Реальное лицо в физическом мире. Каждый человеческий прототип владеет уникальным Human ID в качестве своей корневой идентичности, резервируемой через Mnemonic. |
| **Цифровая персона (iFay)** | ИИ-персона, которую физическое лицо создаёт внутри экосистемы iFay. Один человек может владеть несколькими iFay; каждый iFay несёт свой собственный iFay ID, но все iFay привязаны обратно к одному и тому же Human ID. |
| **Публичная роль (coFay)** | Публично ориентированная совместно используемая роль, которая может создаваться и принадлежать как физическому лицу, так и организации. Каждый coFay имеет собственный coFay ID и Verification Code. |
| **Organization** | Компания, команда или иное юридическое лицо. Organization ID публикуется в открытом виде и не требует защиты Dynamic Code. |

Отношения владения и привязки между этими четырьмя видами субъектов формируют скелет системы FayID — подробности см. в [Главе 3 Сущности и связи](./03-sushchnosti-i-svyazi.md).

## Зачем нужен FayID

В традиционном интернете одному человеку часто приходится поддерживать большое количество независимых учётных записей, паролей, сертификатов и токенов в разных системах. Дизайн FayID мотивирован тремя ключевыми потребностями:

1. **Один человек, одна идентичность, агрегирование множества тикетов**: физическое лицо владеет единственным Human ID и может обменивать его на любое количество традиционных аутентификационных тикетов (пароли, сертификаты, токены доступа, смарт-контракты и т. д.), не запоминая каждый из них.

2. **Конфиденциальность корневой идентичности**: Human ID — это корневая идентичность, и она никогда не должна появляться в публичных коммуникациях. Внешние взаимодействия используют ограниченный по времени Dynamic Code, который автоматически ротируется при истечении; Dynamic Code, сгенерированные в разное время, не могут быть скоррелированы между собой.

3. **Фундамент для Global Merit Chain**: FayID — это идентификационный уровень долгосрочной системы репутации экосистемы iFay, Global Merit Chain. Записи репутации должны накапливаться со временем, никогда не раскрывая корневую идентичность физического лица — FayID разрешает это противоречие через необратимую ссылку — opaqueRef.

## Долгосрочное видение: Global Merit Chain

Global Merit Chain — это долгосрочное видение экосистемы iFay: децентрализованная система записи репутации, которая накапливается со временем. В этой системе:

- iFay ID, coFay ID и Organization ID служат открытыми идентификаторами субъектов для записей репутации и видны on-chain.
- Репутация физического лица ассоциируется опосредованно через необратимую ссылку, что сохраняет непрерывность репутации, защищая при этом корневую идентичность.
- Примитивы идентификации, владения и отзыва, предоставляемые FayID, являются предпосылками для функционирования Global Merit Chain.

> FayID — это не сама Global Merit Chain; это лежащий в её основе фундаментальный идентификационный уровень. Без стабильной, проверяемой, сохраняющей конфиденциальность идентификационной системы записям репутации не к чему привязываться.

## Как читать этот blueprint

Этот blueprint организован в виде отдельных файлов по главам. Для первого прочтения мы рекомендуем следующий порядок:

1. **Глоссарий** ([Глава 2](./02-glossarii.md)): создать общий словарь
2. **Сущности и связи** ([Глава 3](./03-sushchnosti-i-svyazi.md)): понять владение и привязку между четырьмя видами субъектов
3. **Учётные данные и жизненный цикл** ([Глава 4](./04-uchetnye-dannye-i-zhiznennyi-tsikl.md)): узнать, как создаются и истекают Dynamic Code, Verification Code и Authorization Grant
4. **Auth Exchange** ([Глава 5](./05-obmen-autentifikatsii.md)): увидеть, как FayID заменяет традиционную аутентификацию
5. **Конфиденциальность и интерфейс GMC** ([Глава 6](./06-konfidentsialnost-i-interfeis-gmc.md)): понять жёсткие ограничения конфиденциальности и границу on-chain интерфейса
6. **Открытые вопросы** ([Глава 7](./07-otkrytye-voprosy.md)): просмотреть открытые проблемы, которые текущий уровень протокола оставляет нерешёнными

Каждую главу можно читать самостоятельно, но первое сквозное прочтение помогает построить полную ментальную модель.
